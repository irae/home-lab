When adding SSH to a Docker stack, use container port 22 and the next available host port in the 22xx range. Reuse `local-llm-sandboxed/sshd-run.sh` and copy `/home/irae/.ssh/authorized_keys` at image build time. See [README.md](README.md) for current assignments, rebuild guidance, and the container-user/access model. Agents and coding sessions must use an existing unprivileged application account. Root may run initialization and sshd, but configure SSH for key-only application-user access with root login disabled. Plain Docker exec inherits the container's default user; document explicit `--user` and `HOME` arguments, and show a maintenance-only warning in interactive root Bash shells. Preserve authoritative application configuration/environment and audit user work before changing ownership or recreating containers.

Do not write fixed IP addresses, disk UUIDs, or other values that change into repo files. Use hostnames, CIDRs, or placeholders such as `<data-disk-uuid>`. See the host access rule in [README.md](README.md).
