An external GPU box for local LLMs

Two RTX 5060 Ti now, room for four. What they run, what the data says, and how the build can grow.

Where this lands

Two 16 GB cards are enough for a 27B model with long context. The setup that pays for the build is Qwen3.8-27B in NVFP4 on vLLM, at 67.3 tok/s near 120K tokens. In llama.cpp, Qwen3.8-27B at 4-bit with an 8-bit KV cache needs about 22 GiB at 131K tokens and 28 GiB at the full 262K, out of about 31 GiB usable. The first step costs R$ 14,019–17,067 (US$ 2,745–3,342) before I sell the old parts. Qwen's big preview model, Qwen3.8-Flash-Next, needs four cards and more RAM, so it stays on paper.

  • One shared chipset link. All chipset ports reach the CPU over one DMI 4.0 x8 link, about 15.8 GB/s. The SSDs, SATA, USB and the 2.5 Gb network use it too.
  • No lane sharing. The manual lists none between these ports. M.2_2 also takes SATA drives.
  • BIOS. Version 4301 from April 2025 has Intel microcode 0x12F. Version 4505 from December 2025 is a security and ME firmware update.
  • Bifurcation. BIOS 3101 added "PCIe Bifurcation options for GPU with M.2 storage". I could not confirm an x8/x8 mode.
  • Video outputs. The back panel has DisplayPort and HDMI. They work only with a CPU that has integrated graphics.
  • Memory speed. The manual lists DDR4-3200 as standard and up to 5333 with overclocking. DDR4-3200 is enough for this build. Faster memory means a DDR5 board, a whole new build.

The case limit

The case fits one GPU, in slot 1. A 2-slot card does not fit in slot 2. So the RTX 3070 cannot move down to free slot 1, and no RTX 5060 Ti fits inside. Every new GPU goes into the second case. In slot 2, only a single-slot card fits, like a switch card or a riser adapter.

The ideas

  • New GPUs in a second case next to the desktop, on a PCIe switch card.
  • A CPU with integrated graphics, so slot 1 is free for the switch.
  • More RAM, for models that keep part of their weights in system memory.
  • Routes that keep the RTX 3070: M.2 risers, or the switch in slot 2.
  • A faster Gen5 switch.

The faster stack lost on format. Four long-context answers were right but came back wrapped in JSON code fences, and a coding agent that parses replies breaks on that. Both stacks got all long-context retrieval answers right. The stacks differ in engine, weights, KV cache and draft settings, so this does not prove NVFP4 is worse than Q6_K. The repo says that too.

Coding

The coding signal comes from the model cards, not from the repo. No card publishes HumanEval, MBPP or Aider scores, so it rests on SWE-bench and LiveCodeBench.

The repo's own 8 code cases say little. Both stacks scored 8 out of 8, and the suite never runs the generated code. The data tells a lot about speed, context and output format, and almost nothing about whether the code works.

The repo owner serves these models to coding agents through an OpenAI-compatible API, with setup notes for Open WebUI, Cline, Cursor and OpenCode. There is no test of prose or creative writing. The trap they hit most is thinking mode. Qwen can spend the whole output budget on hidden reasoning and return nothing visible. They use 1,024 tokens with thinking off, 4,096 for light coding and 8,192 or more for hard reasoning.

How much the PCIe link matters

llama.cpp splits a model by layers by default, so only small activations cross between cards. vLLM tensor parallel does an all-reduce at every layer, which sends more data over the bus. The repo's hardware doc warns that x16/x16, x16/x4 and x4/x4 results do not compare directly.

How data moves between the cards

With the stock NVIDIA driver, a GeForce card cannot write straight into another card's memory. So data from GPU 0 goes up through the switch into system RAM, then back down through the switch to GPU 1. The CPU does not compute on that data. It sets up the copies, and the cards move the bytes with DMA. With a peer-to-peer driver, and a switch that allows it, the switch forwards the data from GPU 0 to GPU 1 and it never touches the CPU or RAM.

How much data moves depends on the split mode.

  • Layer split, the llama.cpp default. Each token crosses once between the two halves of the model. For Qwen3.8-27B that is one vector of 5,120 numbers, about 20 KB. A 512-token prefill batch sends about 10 MB. Against 15.8 GB/s per card, the trip through RAM costs almost nothing.
  • Tensor split in llama.cpp, tensor parallel in vLLM. Both cards work on every layer and sync their results several times per layer. Here the traffic is real, and peer-to-peer helps. The club-5060ti NVFP4 run still reached 67.3 tok/s over PCIe 3.0 x8, and the repo mentions no peer-to-peer patch.
  • The CPU keeps some work. It runs sampling, schedules each step, and does the n-gram table lookups for a model that keeps that table in RAM. For a 27B model on two GPUs that is a light load.

Peer-to-peer decides what a switch gives

NVIDIA blocks peer-to-peer transfers on GeForce cards in the stock driver. Without them, all GPU-to-GPU traffic goes up to the CPU and back down. The patched driver aikitoria/open-gpu-kernel-modules, version 610.57.04, lists RTX 5060 Ti support. It needs Resizable BAR, Above 4G Decoding and IOMMU passthrough. I found no report of it on an RTX 5060 Ti behind a switch.

A patched driver also drives every NVIDIA card in the machine. With the monitor on integrated graphics, a driver problem cannot take the desktop down.

Qwen3.8-Flash-Next, the big one

This part is an experiment. The model I expect to use every day is a dense 27B-class model with the Qwen4 architecture, if Qwen releases one.

Qwen released Qwen3.8-Flash-Next on 26 August 2026 as a preview of the Qwen4 architecture.

  • Size. 125B parameters with 6B active, a MoE with 512 experts, 10 routed and 1 shared per token. A 51B n-gram embedding table and a 4B MTP draft layer come on top.
  • Architecture. 48 layers, three Gated DeltaNet layers then one Qwen Sparse Attention layer, repeated. The context is 262K tokens.
  • The n-gram table. It is a lookup inside the GGUF, named per_layer_token_embd. Each token reads about 2.7 KB from it, so it can live in system RAM or on SSD through mmap.
  • Software. Mainline llama.cpp supports it since PR #27742 of 27 August 2026. The faster EngramHalo.cpp fork runs only on AMD Strix Halo. Users run it with -ot per_layer_token_embd=CPU, -ncmoe N and --load-mode mmap.

The ideal layout on four cards

The n-gram table stays in RAM. Everything else, the drafter and a 262K context stay on the GPUs, with nothing on the CPU. I read the tensor sizes from the unsloth GGUF file headers. Four cards give about 58 GiB.

14.5 GiB usable per card, my estimate. Larger quants need more than four cards and fall outside this build.

  • Drafter. The "shared" Q8_0 MTP file is 2.60 GiB. It reuses the main embedding and output weights.
  • KV cache. Only 12 of the 48 layers keep one, with 2 KV heads of 256 dimensions. At 262K tokens it takes 6.0 GiB at f16 or 3.2 GiB at q8_0. The MTP layer adds 0.5 GiB at f16.
  • Other context memory. The sparse attention index takes about 0.2 GiB, my estimate. The 36 DeltaNet layers keep a fixed 108 MiB state.
  • Vision and loading. The mmproj file adds 0.84 GiB for images. With mmap loading on, GPU weights leave system RAM after the load.

So the floor is four cards, with UD-Q2_K_XL or UD-IQ3_XXS at almost no margin.

Memory plan

  • 64 GB first. A second 2 × 16 GB kit, ideally the same Kingston part, goes in A1 and B1. That covers smaller future models that keep an n-gram table fully in RAM.
  • 96 GB for Flash-Next for real. A 2 × 32 GB kit plus the current 2 × 16 GB. It holds the table even with worst-case work.
  • Slots. Four 16 GB sticks fill all 4 slots. Going to 96 GB later means swapping one 16 GB pair for the 32 GB pair, and one kit becomes a spare.
  • Speed. Four DDR4 sticks may not hold 3200 MHz with XMP. If the system is unstable, the BIOS speed goes down.

What it runs

Qwen3.8-27B at 3-bit or 4-bit, with a q8_0 KV cache and the built-in MTP drafter, fits the full 262K context on two cards. Only 16 of its 64 layers keep a KV cache. The numbers use a VRAM formula that a user measured on about 30 real llama.cpp loads: the cache grows 42.47 KiB per token with q8_0 and MTP, and built-in MTP adds 668 MiB. Two RTX 5060 Ti have 31.9 GiB. I take off about 1 GiB for the second card's CUDA context and buffers, so about 31 GiB is usable.

No one has posted UD-Q4_K_XL at exactly 262K with q8_0 on two cards yet. The closest real report is two RTX 5060 Ti running Q5_K_M at 215K context with q8_0 KV, MTP and --split-mode tensor. By the measured formula that load needs about 27.8 GiB, a little more than UD-Q4_K_XL at 262K. It decodes at 30 tok/s on PCIe 3.0 x8 across two CPU sockets, and a second user with the same cards gets 55 to 60 tok/s at 197K context on PCIe 4.0. So q4_0 KV is not needed, and UD-Q3_K_XL stays a spare option. Newer UD-Q4_K_XL files default to 131K, so --ctx-size 262144 has to be set by hand, per this report.

The target is NVFP4 on vLLM. The reference machine runs it at 67.3 tok/s near 120K context, with an FP8 KV cache and 15.6 GB used per card. The same model runs at 38.6 tok/s with Q6_K in llama.cpp. vLLM tensor parallel moves more data between cards, and behind the switch in slot 1 each card gets twice the reference machine's link. Nobody has published a Q4_K_XL number on two cards yet.

  • 13th and 14th gen stability. High voltage requests caused instability and degradation on these chips. BIOS 4301 has microcode 0x12F, which prevents new damage but cannot repair a damaged chip. Used 13th and 14th gen CPUs from unknown sellers are a risk. 12th gen is not affected.

  • The F models. An i9-14900KF or i5-12400F has no graphics and does not solve the monitor problem.

Build notes

  • Power plugs. Four GPUs and four baseplates want eight PCIe plugs. The RM1000e ships with fewer, so cards three and four need extra modular cables. The MSI MAG A1000GL has 6 plugs, but I found no price.
  • Cables. Gen4 over SlimSAS is sensitive to length and quality. If a card drops off the bus, the slot goes to Gen3 in the BIOS.
  • Firmware and kernel. Above 4G Decoding and Resizable BAR on. The Level1Techs PEX88048 build needed pci=realloc.
  • Settings from the repo. tensor-split = 50,50 exactly, because 51,49 asserts in tensor mode. Output budgets set before judging quality.
  • Checks. nvidia-smi topo -m shows PIX for cards on the same switch. The link width and gen:
nvidia-smi --query-gpu=index,name,pcie.link.gen.current,pcie.link.width.current --format=csv

No RTX 5060 Ti result behind a PCIe switch exists in club-5060ti yet, so this build would be a new data point.

2. 64 GB of RAM

A second 2 × 16 GB DDR4-3200 kit costs R$ 1,700–1,800 (US$ 332–352). My work plus a 26.8 GiB n-gram table then fits, which covers smaller future models built the same way. The memory plan above has the details.

3. Four cards and 96 GB

Two more RTX 5060 Ti cost R$ 7,918–8,600 (US$ 1,550–1,684). A 2 × 32 GB kit costs R$ 4,950 (US$ 969). Together that is R$ 12,868–13,550 (US$ 2,520–2,653), plus PSU cables. It runs Qwen3.8-Flash-Next UD-Q2_K_XL or UD-IQ3_XXS fully on GPUs with the table in RAM, at almost no margin. Nobody has published a speed for that layout. With some experts in RAM instead, 4 cards and 64 GB fit UD-Q4_K_XL at an estimated 15 to 20 tok/s.

4. Keeping the RTX 3070

Both routes here keep the 3070 in slot 1 for games and the i5-12400F. Neither allows peer-to-peer, so llama.cpp --split-mode layer is the mode, and vLLM tensor parallel is off the table. The stock NVIDIA driver is enough. Small jobs like Whisper or OCR can run on the 3070, with CUDA_VISIBLE_DEVICES keeping llama.cpp on the 5060 Ti cards.

M.2 risers

Each M.2 slot takes an M.2 to OCuLink or M.2 to SFF-8654 4i adapter, and a cable runs to a dock in the GPU tower. An M.2 to OCuLink dock with 6-pin power, like this one or this one, costs R$ 182–239 (US$ 36–47) with tax on AliExpress.

The switch in slot 2

The single-slot switch card fits in slot 2, but the whole GPU tower then shares one PCIe 3.0 x4 link through the chipset, about 3.9 GB/s. With the stock driver, GPU-to-GPU traffic goes up that link and back down, so the switch gives no more than a plain x4 riser. One GPU in slot 1 and others behind a switch in slot 2 have no peer-to-peer path between them.

5. A Gen5 switch

The RTX 5060 Ti has a PCIe 5.0 x8 link, and a Gen4 switch runs it at half that. Only a Gen5 switch gives each card its full link. With layer split the gain is small. With tensor parallel the bus is the limit, so the gain is larger.

  • GPU-side adapters. An MCIO 8i to PCIe x16 Gen5 adapter with a 500 mm cable costs R$ 117–166 (US$ 23–33) each with tax.
  • Short cables. Vendor guides keep passive Gen5 MCIO under about 40 cm, and the 50 to 75 cm kit cables are at or past that limit. The GPU tower would have to sit right next to the desktop.
  • Failed links. An NVIDIA card can fall to Gen1, not Gen4, when Gen5 training fails, per issue #1010. Forcing Gen4 gives the same speed as the PEX88048.
  • No GeForce reports. I found nobody running a GeForce card on these Gen5 switches, and nobody with a working peer-to-peer driver on an RTX 5060 Ti.
